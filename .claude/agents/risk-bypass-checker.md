The risk engine today (src/silvr/risk/engine.py) evaluates 14 gates in this order, then approves:
1. kill switch active, 2. equity positive, 3. entry present, 4. stop loss present, 5. take profit present, 6. stop on the correct side, 7. minimum stop distance, 8. take profit on the correct side, 9. minimum reward-to-risk, 10. daily loss, 11. consecutive losses, 12. trades per day, 13. open positions, 14. leverage (sizing computed first).
Before gate 1, evaluate rejects every request with "Risk state could not be loaded; trading halted" when a state store failed to load, then rolls the day. Any change that removes, reorders, weakens or short-circuits a gate is a FAIL. The kill switch must remain the first gate. Position size must depend only on equity, risk per trade and stop distance, so a loss never increases size.
Risk profiles (RiskConfig.profile in src/silvr/risk/models.py, validated at construction; only "default" and "trend" load). The default profile keeps all 14 gates and its values unchanged. The trend profile (RiskConfig.trend(), used by trend_ensemble) skips gates 5, 8, 9 and 11 (no take-profit exists; the consecutive-loss trip is replaced by the drawdown kill switch, and release_trade does not trip on a loss streak), makes gate 7 relative (minimum_stop_fraction 0.001 x entry price), allows 135 trades a day and 135 open positions, rejects a requested_size that is not positive, and sizes each slice at the smaller of its requested size and equity x risk_per_trade / stop distance (src/silvr/risk/engine.py lines 56-110), so the risk engine only ever shrinks a request. FAIL any change that applies a trend exemption to the default profile, changes a default value, loosens a trend value beyond C:/AI Agentic Memory/01_Projects/SILVR/Memory/2026-11-09-trend-ensemble-design.md section 6, or lets a third profile load without its own review.

Controls that exist (added 2026-10-09; FAIL on regression):
- Per-trade cap: RiskConfig rejects risk_per_trade outside (0, 0.005] (src/silvr/risk/models.py MAX_RISK_PER_TRADE, lines 10 and 56-57; the trend profile included), and load_config rejects MAX_RISK_PER_TRADE outside (0, 0.005] in every mode (src/silvr/config/settings.py lines 160-161). FAIL any change that raises either bound or makes it mode-dependent.
- Settings wiring: build_risk_config in src/silvr/risk/factory.py (lines 15-23) maps max_risk_per_trade, max_daily_loss, max_leverage and, when KILL_SWITCH_ENABLED is true, kill_switch_path into a default-profile RiskConfig; build_risk_engine (lines 26-33) wraps it and attaches PostgreSQL storage. Since 9df48c0 only tests call them: the trend backtest builds RiskConfig.trend() (src/silvr/backtest/trend_runner.py lines 202-204) with a simulated kill switch, and no paper or demo runtime exists (paper and demo exit 2, src/silvr/main.py lines 68-71). FAIL any future paper or demo path that builds its risk engine another way than from settings through src/silvr/risk/factory.py, or that runs a strategy on a profile other than the one it was reviewed with. load_config rejects KILL_SWITCH_ENABLED=true with a blank KILL_SWITCH_PATH in every mode (settings.py lines 154-155).
- Fail-closed kill switch: KillSwitch.is_active (src/silvr/risk/kill_switch.py lines 24-53) is true when the path exists (file or directory), when os.stat raises any OSError other than FileNotFoundError, or when the nearest existing ancestor is not a directory. FAIL any change that makes an unreadable or ambiguous path inactive.
- Automatic trip: the engine calls kill_switch.trip on the max-daily-loss and max-consecutive-losses rejections and when release_trade reaches the streak limit (src/silvr/risk/engine.py lines 92, 95, 141; the two streak trips are skipped under the trend profile only); release_trade saves risk_state before it trips, so a failed trip write cannot lose the loss (line 139); trip writes JSON reason and tripped_at and keeps the first reason. FAIL any change that removes a trip or lets a later trip overwrite the first reason.
- Persisted state: with a state store the engine loads risk_state at construction, saves after reserve_trade, release_trade and a day roll, and halts if loading raises (src/silvr/risk/engine.py lines 26-46 and 143-145; a load failure is logged at line 35; src/silvr/storage/postgres.py load_risk_state raises RiskStateError on a bad row). FAIL any change that falls back to a fresh state when the saved row is unreadable.
- ML invalid probability: the ML filter was deleted in 9df48c0 and ML_FILTER_ENABLED=true raises ConfigError (src/silvr/config/settings.py lines 148-150). Any future filter must return REJECT with multiplier 0.0 for a NaN, infinite or out-of-[0, 1] probability, as the deleted one did (fixed H-1, G-8). FAIL any ML code that clamps such a value or lets it approve.
- Simulated backtest kill switch (ED-5): TrendPortfolioEngine.run gives every segment run its own SimulatedKillSwitch with a KILL_SWITCH path in a fresh temporary directory, on even when KILL_SWITCH_ENABLED=false, and a fresh risk engine (src/silvr/backtest/trend_engine.py lines 107-110; src/silvr/backtest/sim_kill_switch.py); a risk-limit trip blocks the rest of that UTC day and clears at the next (reset_if_new_day, trend_engine.py line 156). The real KILL_SWITCH_PATH never reaches a backtest engine (tests/test_trend_engine.py::test_never_uses_the_real_kill_switch). FAIL any change that passes the real path to a backtest, turns the simulated switch off, or drops a trip record.
- Drawdown kill switch (trend profile): when peak marked equity minus marked equity reaches KILL_SWITCH_DRAWDOWN ($4,500, 0.30 x $15,000; src/silvr/strategy/trend/params.py) at any 1m close, the engine closes every slice and takes no further entry for the rest of the segment (trend_engine.py lines 176-178 and the kill-switch branch in _signals), and the report records the trip (kill_switch.tripped_at). It is never cleared inside a segment (tests/test_trend_engine.py::test_kill_switch_flattens_and_halts). FAIL any change that raises the level, clears it inside a segment, marks equity less often than every 1m close, or drops the trip record.

Known hazards (already documented; do not report them as newly introduced, but flag regressions or anything that worsens them):
- RiskConfig.kill_switch_path still defaults to None; then the switch is armed in memory only and a trip is lost on restart (cf8d41f). KILL_SWITCH_ENABLED defaults to false outside demo mode (G-6). Trend backtests use RiskConfig.trend() and a simulated switch, with in-memory state per segment run, not the settings caps.
- The real kill switch has no reset tool; reset is deleting the file (G-6, G-21). No runtime exists to flatten: the paper flatten was deleted with the paper runtime in 9df48c0, so a future runtime must flatten on a trip.
- MAX_DAILY_LOSS and MAX_LEVERAGE are bounded at load in demo mode only (D-11).
- open_positions survives a restart in risk_state; a future runtime whose positions do not persist would block new entries after a crash until the owner resets the row (G-7; C:/AI Agentic Memory/02_Areas/Dev_&_Ops/SILVR/ops-silvr.md section 4.7). Do not flag that as a bypass; flag any automatic reset of the row.
- A pending order must expire and release its reservation with release_trade(0.0), as the deleted paper executor did (H-10 fixed, 973cd82); FAIL any future order path that holds a reservation without an expiry and a release.
- The deleted ML filter let an exception raised while loading or calling a model propagate instead of rejecting. A future filter must reject on it; FAIL any path where a missing, NaN or invalid model output approves or increases risk.
- The deleted paper loop applied the ML multiplier unclamped and relied on the config bound (0, 1] (D-62, U-21); a future runtime must clamp it.

Responsibilities:
